# Markdown 全格式测试文章（一级标题）

这是一篇用于验证 md-to-wechat 转换效果的测试文章，涵盖公众号文章中常见的全部 Markdown 格式。为了让你能清楚地观察两端对齐、段落间距与行距的表现，这一版特意把正文写得更长、段落加得更多。这一段继续填充足够的文字：排版是否舒服，往往要到第五六行才能看出来，短段落什么问题都藏得住，长段落才会把行高、字距、对齐方式的毛病一一暴露。

继续第二段。中文排版的讲究，一半在字里行间，一半在留白呼吸。字与字之间太挤，读者就喘不过气；行与行之间太密，眼睛就找不到下一行的入口。这段话没有别的意义，就是让你在手机宽度下多看几行连续的中文，感受一下 17px 字号、0.5px 字间距、1.8 倍行高组合起来的阅读节奏，顺便看看逗号、句号、顿号落在行尾行首时的样子。

第三段来看看中英文混排。在 EDA 这个行业里，RTL、PPA、Spec、Agent、Vibe Coding 这些英文词汇总是夹在中文句子里出现，它们长短不一、基线不同，最考验两端对齐的功力：左对齐排版里，这些单词会让右边缘犬牙交错；两端对齐排版里，浏览器会把空隙均匀摊进字缝，换取一条笔直的右边线。这一行再写长一点，让混排的效果多持续两行，方便你对比。

## 二级标题：文本样式

这一节集中测试**行内文本样式**。包括：**加粗文本**、*斜体文本*、~~删除线文本~~、`行内代码 code`，以及**一段跨行的超长加粗文字，用来复现之前微信检测器误报叠字的场景，这段加粗长到必定在手机上折行，看看转换后的 HTML 是否还会触发 line-height 检测**。

还有混合格式：**加粗里套 `代码`**，以及 [一个超链接：GitHub](https://github.com) 的显示效果。链接在公众号里的地位比较尴尬：正文里的外链点不动，只能看个颜色，所以多数作者把链接降级成纯文本提示。这里保留它，纯粹为了验证颜色和下划线样式是否生效。

再接一段普通文字，观察加粗段落和普通段落交替出现时，视觉上是否连贯。好的排版应该让强调融进正文，而不是跳出来打人一拳。这段继续写长，写到第三行，看看段落内部每一行之间的缝隙是否均匀，有没有哪一行突然贴近或者远离它的邻居。

#### 四级标题：引用与代码（左侧黑竖线样式）

> 这是一段引用。引用通常用于转述官方说明、新闻稿原文或名人名言。这段也写长一点，测试引用块在多行情况下的背景色、左边框和行高表现。引用的字号与正文相同，但颜色更灰、背景更浅，应该在版面上往后退半步，让读者一眼认出"这不是作者说的话"。

行内代码：`python md2wechat.py article.md --output out.html`，嵌在句子里看它的高度是否压过正文行高。

代码块：

```python
def convert(md_text, style):
    html = markdown.markdown(md_text)
    return apply_inline_styles(html, style)

# 注释：测试代码块的深色背景、等宽字体与折行表现
for i in range(3):
    print(convert(f"article_{i}.md", "default"))
```

代码块下面接一段正文，测试深色块与白色正文之间的过渡是否生硬。手机屏幕上深色代码块是很抢视觉的元件，上下留白不够就会显得拥挤，这段文字顺便把代码块和下文隔开一点距离。
